## Measured facts (host A, 2026-11-08, agy 1.5.3)

- agy auto-updated to 1.5.3 (binary mtime 2026-11-08T15:31:26+0900).
- A custom agent whose `tools:` list is `view_file, grep_search, list_dir, find_by_name, finish` (A's
  `triad-readonly-review`) is offered only `read_file` (parameters `Path`, `StartLine`, `EndLine`, `ByteOffset`),
  `manage_task` (`Action`, `TaskId`, `Input`) and `finish`. With `read_url_content, search_web` added (A's
  `triad-readonly-research`) it is offered `read_file`, `manage_task`, `search_web`, `finish`. `list_dir`,
  `grep_search`, `find_by_name`, `view_file` and `read_url_content` are not offered; a call by name is impossible. (The
  offered set is the model's report of its declarations; agy prints none — spike § Limits.)
- The stream's `tool_name` and `tool_info.name` for a file read are `read_file`, with the path in `Path`; the
  PreToolUse hook receives `read_file` too. `init.tools` still lists the old names and is not the offered set.
- Effect on A: the wrapper's admission census, the read-audit digest, the review hook's allow set and the read-audit
  gate know only `view_file` (the gate matches `view_file` + `AbsolutePath`), so every agy review leg is refused —
  `admission-refused` / 65 on a plain call, read-blind in a review round.

## Shared rule (R-CONTAIN, both hosts)

A host's agy allow list, its read-audit read classification and its packet-read evidence accept `read_file` (path
parameter `Path`) alongside `view_file` (`AbsolutePath`). The old names stay accepted for agy builds before 1.5.3.
`manage_task` stays off-list: an executed `manage_task` still withholds the answer (the existing census rule).
Nothing else is added to an allow set.

## Capability loss on 1.5.3

No native listing, content search, name search or URL fetch: an agy leg reads only the paths it is given. The shared
Google leg prompt (`prompts/leg-google.md`, which names `view_file` / `grep_search` / `list_dir` / `find_by_name`), the
web-evidence clause (`prompts/investigation.md`, which requires citing only pages fetched with `read_url_content`) and
C72's search-profile premise (a profile that "explicitly enables native read/content-search/name-search/listing") no
longer hold on 1.5.3. The prompt files and the packaged bundle copies are not changed by this record: they move with a
library release after the owner's answer below.

## Owner question (DL-179)

On agy 1.5.3 the agy route can no longer fetch a page, so the web-evidence clause cannot be met there. Which way: (a)
cite `search_web` results as snippets only, marked as such; (b) no agy web research — the agy leg runs without web;
(c) route web evidence to another leg (codex `--search` or the claude leg). Leader option labels, not owner words.

## Web-tool facts and the owner's ruling (2026-11-08, appended)

Measured on host A the same day (agy 1.5.3; evidence
[spikes/2026-11-08-agy-153-toolset.md](../spikes/2026-11-08-agy-153-toolset.md) § Web-tool probes, files `p1.jsonl` -
`p4.jsonl`, `p3.err`):

- `search_web` works with no setting; it returns an AI-synthesized Markdown summary plus `Sources:` Vertex AI Search
  grounding redirect URLs, with no page text and no page titles.
- No page-fetch tool is offered in print mode, not even to the default agent. `read_url_content` is registry-known but
  not offered (issue #1353, open, labelled bug, assigned, no workaround; reported on agy 1.4.8); the operator's
  `read_url(*)` allow does not change it.
- A custom agent `tools:` list naming a tool the registry does not know aborts the run (`unknown component: tool
  "read_url" not found in registry`); `read_file`, `read_url_content`, `search_web` and `finish` are registry-known.
- `excludeDefaultComponents: true` does not remove `manage_task` on 1.5.3 (issue #1015) — this settles the open
  "not probed" item of the spike's § Limits; the shared rule above (`manage_task` stays off-list) is unchanged.
- Official: the permissions page names `read_url` as the gate for page reading, default Ask
  (<https://antigravity.google/docs/permissions>); the SDK tools page says web search and URL fetching are enabled by
  default, an SDK statement, not a CLI one (<https://www.antigravity.google/docs/sdk/tools/>).

Ruling: [D-AGY-WEB-EVIDENCE-20261108](owner-register.md#D-AGY-WEB-EVIDENCE-20261108) answers the owner question above
(DL-179, now RULED). Under the leader's recorded reading, web stays on for every review leg; an agy leg's web fact is a
search pointer, never fetched evidence; a web fact that decides a finding is verified on the raw page by a leg that can
fetch (codex `--search`, the claude leg) or by the leader before it is acted on. The rule sentence is in
[R-REVIEW-WEB](../reference/review-rules.md#R-REVIEW-WEB), with a pointer from R-INVEST. The prompt texts
(`prompts/leg-google.md`, `prompts/investigation.md`), their packaged bundle copies and `tests/test_prompts.py` change in
the next library release (DL-180); this record changes none of them.

## Alias clash, 2026-11-08

Measured on agy 1.5.3 (spike `../spikes/2026-11-08-agy-153-toolset.md` § Alias clash): `view_file` in a custom agent's `tools:` resolves to `read_file`, and listing both aborts the run ("tool name conflict: multiple tools resolved with name \"read_file\""). A host keeps one of the two names in `tools:` (host A keeps `view_file`, which old builds also know) and names `read_file` wherever the model or the census must recognise the file read: the agent's prose allowlist, the census, the hook allow set and the read-audit gate.

## No backward compatibility (owner ruling), 2026-11-08

[D-AGY-MIN-VERSION-20261108](owner-register.md#D-AGY-MIN-VERSION-20261108): host A requires agy >= 1.5.3 on its read-only agy path and tells an older build to run `agy update` (refused before any spawn, `config-conflict`); its agent `tools:` lists name only the 1.5.3 tools (`read_file`, `finish`; research adds `read_url_content`, `search_web`), so the alias clash above no longer arises, and its census, hook and read-audit gate accept `read_file` only. Host B may keep the older names or adopt the same floor.
